# 第一章《林知秋的最后 72 小时》— 游玩与部署指南

## 一、怎么开始玩

双击打开 **`chapter1/index.html`**（入口私信）即可。整条线是自包含的静态网页，无需联网、无需后端。

> 建议用 Chrome / Edge / Safari。Node 4 的录音用浏览器自带语音合成「朗读」，需要系统装有中文语音包；没有也没关系，会自动降级为逐句显示文字稿。

## 三、三层防卡关暗示（已内置）

每个谜题的提示已改为**渐进式**（2024 难度重构后）：
1. **叙事暗示** — 藏在正文里，正常阅读可注意到（博客简介、录音台词、笔记措辞）。页面上**不再有**"操作说明书"式提示。
2. **渐进报错** — 输错 1–2 次只说"错误"；3–4 次给方向性暗示；5 次以上才给接近解法的提示。
3. **折叠兜底** — 查源码关用两层"需要帮助？"折叠提示，不点不剧透；直达链接藏在第二层里。

四个密码各不相同、零复用：藏头句 → 墙上日期 → 频率 → 倒序名。照片上三行信息各司其职（公司名=指向下一站，日期=笔记的门，频率=内网访问码）。

## 四点五、其他部署方式（备选）

试水阶段推荐免费静态托管，三选一：

- **Netlify Drop**：打开 app.netlify.com/drop，把整个 `chapter1` 文件夹拖进去，秒出公开网址。
- **Vercel**：`vercel` CLI 或网页导入，根目录指向 `chapter1`。
- **GitHub Pages**：把 `chapter1` 推到仓库，Settings → Pages 开启。

> 进阶沉浸：如果想让三个站点像真的不同网站，可分别部署到不同子域名（如 `linzhiqiu.xxx`、`echotech.xxx`），再把各页面里的相对链接改成绝对链接。试水阶段用同一目录的相对链接即可。

## 5.5、已知限制（试水版可接受，正式版再处理）

- **答案明文写在前端 JS 里**：玩家「查看源代码」就能看到所有判定字符串。而 Node 3.5 恰好会教玩家查源码——好奇的玩家可能顺手看其他页面源码而破功。试水阶段可接受（剧情向玩家通常不会这么玩）；正式公开版建议把判定改为哈希比对（如 SHA-256），或上轻量后端校验。
- **关卡可被 URL 直跳**：知道文件名就能绕过谜题直接访问任何页面。静态站固有限制；多数 ARG 玩家视「跳关」为自损体验，影响有限。
- **录音依赖浏览器语音合成**：无中文语音包的设备自动降级为逐句文字稿（已内置），但「听录音」的氛围会打折。正式版建议录一段真人音频替换。

- **改藏头答案**：同时改 `blog-melody.html` 的 8 段段首字 + 该页 JS 里的 `回声在旧楼醒来了` 判定。

- **照片暗部难度**：`blog-notes.html` 里隐藏文字的 `fill` 色值（当前 `#15130f` / `#141210` / `#16140f`）越接近背景 `#100e0a` 越难、越远越易。已实测：默认状态仅见模糊笔迹，拖暗房滑块到高档（约 亮度 700%+ / 对比度 400%+）字迹清晰浮现。
