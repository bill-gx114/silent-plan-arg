# 《寂静计划》玩家旅程连续性设计

## 目标

在不降低取证与推理参与感的前提下，消除玩家不知道下一步、误以为进度已保存、提前进入结局以及章节跳转不稳定的问题。最终让第一至第三章形成一条可在 GitHub Pages 内完整访问的主线。

## 设计原则

1. 玩家负责判断，系统负责记忆。
2. 完成谜题后必须出现明确的下一步。
3. 结局是调查结果，不是首页快捷入口。
4. 章节切换留在同一站点，不依赖外部妙搭地址。
5. 保留三个站点和各章节的视觉身份，不进行与主路径无关的全面重绘。

## 第一章

谜题成功后自动把 `AFTERIMAGE`、`BLACKOUT`、`CYPRESS`、`DRYRUN` 写入现有案件状态。案件笔记继续保留手动输入作为兼容入口，但主要展示四项证据的来源、取得状态、完成数量、令牌状态和下一步建议。

未集齐四项证据时不显示结局。集齐四项后开放“公开证据”和“暂缓并保存”；再取得 `FOLLOW-THE-TIDE` 后开放真结局。

每个核心谜题成功后提供唯一、明确的主行动，直到返回案件笔记形成结论。

## 第二章

加密会话保留逐条出现的节奏，但提供“立即显示全部”按钮；启用减少动态效果时直接显示完整会话。第二、三章增加轻量级系列状态条，展示当前章节、调查目标和章节入口。

## 第三章

构建脚本同时发布 `chapter3/`。第二章结尾改为站内链接 `../chapter3/index.html`，不再依赖外部妙搭地址。第三章结束只预告尚未发布的第四章。

## 兼容与测试

保留 `silent-plan-case-v2` 存储键和手动证据输入。测试覆盖自动记录、结局门槛、笔记进度、连续导航、跳过对话、本地第三章链接、构建路由和静态链接。

## 非目标

- 不重写第二、三章全部视觉样式。
- 不修改现有剧情和谜题答案。
- 不新增账号、云存档、服务器或第四章。
