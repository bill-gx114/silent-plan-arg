# 《寂静计划》第四章《鹿原 · 为你好》设计

## 定位

第四章是当前故事的阶段终章，不是整个世界观的最终章。玩家在鹿原完成两项实质目标：

1. 救出仍被控制在声纹采集系统中的林知秋。
2. 公开鹿原“记忆健康”试点的伪造审批与强制实验链条。

章节结尾关闭鹿原、林知秋和前三章城市链条的主要悬念，同时揭示更高层授权节点 `WHITE-TOWER / 白塔`，为后续故事保留明确但不影响本章完成感的入口。

## 设计原则

1. 玩家负责判断，系统负责记录。
2. 谜题答案必须由至少两份页面内证据支持。
3. 每个谜题成功后只提供一个明确主行动。
4. 结局条件未满足前，不展示不可达的结局入口。
5. 失败提示分层给出方法，不直接泄露答案。
6. 第四章沿用共享章节状态条、减少动态效果、移动端表格滚动和可访问反馈规范。
7. 不依赖外部网站、下载应用、真实账号或不可控网络资源。

## 故事梗概

玩家抵达鹿原后，收到林知秋在海宁留下的延迟消息。她指出“记忆健康”便民服务试点并非治疗项目，而是把回声科技、安眠岛和海宁调制站的成果投入城市级人群控制。

鹿原官方宣称所有参与者均为自愿预约，项目也经过公开听证。玩家首先证明部分“自愿者”从未申请，再重建一场在项目启动后补办的伪造听证会。两条证据共同指向鹿原市协调办公室地下二层，林知秋正被作为声纹模型的高价值样本转移。

最终行动需要同时完成证据镜像和营救路线准备。只执行一条线会得到代价明确的普通结局；正确完成两条准备并在 `04:17` 同步触发，才能救出林知秋并让鹿原项目材料进入无法单点删除的公开镜像。

## 章节结构

第四章使用 `chapter4/` 下的静态页面，不另建后端。页面继续加载 `series/series.css` 与 `series/series.js`，并通过 `data-chapter="4"` 和 `data-objective` 展示当前位置。

### 1. `chapter4/index.html`：延迟消息

林知秋的延迟消息作为章节入口，交代鹿原试点和第一个调查目标。

- 保留逐条出现的节奏。
- 提供“立即显示全部”按钮。
- 启用 `prefers-reduced-motion: reduce` 时直接显示全部。
- 唯一下一步为“打开鹿原记忆健康便民服务平台”。

### 2. `chapter4/portal.html`：便民服务平台

模拟鹿原市政务门户。页面包含项目介绍、公开自愿者名单、预约查询和公示材料。

#### 谜题一：异常自愿者名单

玩家比较三类信息：

- 公开名单中的街道与预约编号。
- 预约回执的申请时间。
- 街道编码规则。

名单中 12 人使用不存在的预约编号前缀，且申请时间早于系统开放时间。玩家需要选择“名单包含未申请居民，所谓自愿并不成立”。

成功后自动记录第四章进度 `volunteersVerified`，并开放公示材料页。

#### 提示层级

1. 先比较编号前两位与所属街道。
2. 再比较回执时间与平台开放时间。
3. 重点检查东七码头街道的 `07` 前缀和 4 月 3 日之前的记录。

### 3. `chapter4/notices.html`：公示材料

页面提供网页版公示、打印版和无障碍朗读文本。三者内容不完全一致。

#### 谜题二：恢复审批批次

- 网页版删除了审批批次。
- 打印版保留尾号 `04`。
- 无障碍文本仍朗读完整值 `LY-MH-04`。

玩家输入 `LY-MH-04` 后，系统记录 `batchRecovered`，并提供唯一下一步“调取该批次听证档案”。

### 4. `chapter4/hearing.html`：听证档案

页面展示：

- 听证会座次图。
- 三份居民代表证词。
- 麦克风编号与发言顺序。
- 门禁进入记录。
- 官方新闻稿。

复杂表格必须放在横向滚动容器内。

#### 谜题三：重建伪造听证

玩家需要把三位代表放回真实座次，并选择结论：

- 2 号代表在其证词发言时尚未进入会场。
- 1 号与 3 号证词包含相同的非公开错别字。
- 新闻稿发布时间早于听证结束。

正确结论是“听证会在项目启动后补办，三份同意证词由协调办公室统一代写”。

成功后记录 `hearingExposed`，揭示：

- 林知秋位于协调办公室 B2 声纹室。
- 内部审批使用上级授权代号 `WHITE-TOWER`。
- 最终行动需要同时准备证据镜像与营救路线。

### 5. `chapter4/operation.html`：双线准备

页面分为两个独立但同屏可见的准备区。

#### 证据镜像线

玩家从六项材料中选择三项构成最小充分证据包：

1. 异常自愿者名单。
2. 伪造听证证明。
3. `WHITE-TOWER` 上级授权记录。

项目宣传册、天气记录和普通预约截图不是充分证据。选择正确后记录 `mirrorReady`。

#### 营救路线线

玩家比较：

- 门禁轮换。
- 地下层供电切换。
- 样本转运电梯时刻。
- 内部广播静默窗口。

正确路线为：

- 从西侧档案通道进入。
- 避开 04:10 样本转运。
- 在 04:17 供电切换后进入 B2。

选择正确后记录 `rescueReady`。

两个准备区都完成后，才显示同步执行表单。

### 6. `chapter4/execute.html`：同步触发

玩家输入执行时间。正确答案为 `04:17`。

系统根据已有状态进入三类结局：

- 仅 `mirrorReady`：公开鹿原证据，但林知秋被转移。
- 仅 `rescueReady`：救出林知秋，但核心审批材料被销毁。
- 两项均完成且时间为 `04:17`：进入完整结局。

如果两项准备都未完成，不允许执行，并明确指向缺失的准备项。

### 7. `chapter4/end.html`：阶段终章

完整结局需要提供清晰的情感回报与事实收束：

- 林知秋脱离声纹室并与玩家直接对话。
- 鹿原试点暂停，异常名单与伪造听证进入公开镜像。
- 陈砚明、程野、苏黎和前三章材料被串成同一条证据链。
- 林知秋说明她主动留下路线，但并未预料到玩家能同时保住人和证据。
- `WHITE-TOWER` 被确认是跨城市授权节点，不属于鹿原任何机构。

页面最后显示“鹿原篇完成”，而不是“故事结束”。后续钩子只作为档案注记，不提供失效的第五章链接。

普通结局同样要有完整文本，明确玩家保住了什么、失去了什么，以及重新调查的入口。

## 状态模型

第四章使用独立存储键 `silent-plan-chapter4-v1`，避免污染第一章案件状态，同时便于重玩。

```js
{
  volunteersVerified: false,
  batchRecovered: false,
  hearingExposed: false,
  mirrorReady: false,
  rescueReady: false,
  executionTime: "",
  ending: ""
}
```

提供纯函数和存储函数：

- `createChapter4State()`
- `loadChapter4State()`
- `saveChapter4State(state)`
- `completeChapter4Step(state, step)`
- `availableChapter4Actions(state)`
- `resolveChapter4Ending(state, time)`

页面只负责收集输入与渲染结果，结局判断集中在 `chapter4/chapter4.js`，便于测试。

## 视觉与页面规范

第四章视觉主题为“温和政务界面下的冷硬控制系统”。

- 第一幕使用浅色政务蓝、宽松留白和标准表格。
- 第二幕转为档案米白与印章红，突出材料冲突。
- 第三幕使用深色调度台，但继续复用统一字段、动作和反馈结构。
- 正文最大阅读宽度约 1120px，单列文本约 720px。
- 页面主容器移动端左右留白不小于 16px。
- 可点击目标最小高度 44px。
- 每页只有一个 `h1`。
- 成功、错误和提示区域使用 `role="status"` 或 `aria-live`。
- 不使用只能靠颜色识别的状态。

## 玩家路径与防卡死

主路径：

`chapter3/end.html` → `chapter4/index.html` → `portal.html` → `notices.html` → `hearing.html` → `operation.html` → `execute.html` → `end.html`

所有页面都提供：

- 当前目标。
- 已完成进度。
- 唯一主行动。
- 返回本章入口。

直接访问后续页面时，页面读取状态并展示缺失步骤及返回链接，不以空白页或无解释禁用按钮阻断玩家。

## 构建与发布

- `scripts/build.mjs` 将 `chapter4/` 复制到 `dist/chapter4/`。
- `chapter3/end.html` 的第四章待续文本替换为站内入口 `../chapter4/index.html`。
- 静态链接测试覆盖第四章全部页面。
- GitHub Pages 工作流继续执行构建与全量测试。

## 测试与验收

### 单元测试

- 第四章初始状态稳定。
- 完成步骤不修改原对象。
- 未完成双线准备时不能获得完整结局。
- `04:17` 仅在双线完成后产生完整结局。
- 普通结局分别对应“公开优先”和“营救优先”。

### 内容契约测试

- 每个页面有语言、视口、标题、一个 `h1` 和章节状态条。
- 每个谜题包含两份以上支持证据和分层提示。
- 听证表格位于横向滚动容器。
- 动态对话支持立即展开和减少动态效果。
- 第三章结尾链接到本地第四章。

### 构建与浏览器验收

- `dist/chapter4/` 包含七个页面及脚本样式。
- 所有本地链接返回 200。
- 从第三章结尾可连续进入第四章完整结局。
- 桌面与移动宽度下没有主要内容溢出。
- 浏览器控制台无错误。
- 刷新后第四章进度保持。

## 非目标

- 不制作第五章。
- 不接入真实市政系统、账号、数据库或云存档。
- 不把第四章状态合并进第一章四枚证据模型。
- 不重写前三章页面视觉。
- 不加入需要音频识别、外部搜索或真实文件工具才能完成的谜题。
