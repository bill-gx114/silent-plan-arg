# 《寂静计划》第一章分层调查网重构设计

## 1. 目标

重构第一章《林知秋的最后 72 小时》，保留林知秋、回声科技、陈砚明、失音症与死人开关等核心设定，将现有线性密码链升级为三个独立妙搭站点组成的分层调查网。

目标体验：

- 单人、电脑优先，手机可阅读但不保证完成复杂取证操作。
- 主线时长 75–90 分钟。
- 隐藏调查线约 30 分钟。
- 主线难度适中，隐藏线面向有经验的玩家。
- 玩家通过交叉验证证据得出结论，而不是依次输入页面中直接出现的答案。
- 主线零人工提示通关率目标不低于 70%。
- 隐藏真结局发现率目标为 20%–40%。

## 2. 设计原则

### 2.1 解谜即叙事

每次操作必须验证人物、动机、时间或事件。删除与剧情无关的藏头、名字倒序、单纯摩斯转译等独立密码题。

### 2.2 玩家主动调查

玩家可以在已发现的材料间自由切换，自行决定先检查哪个站点和附件。页面不持续提供唯一的“下一步”按钮。

### 2.3 关键线索冗余

每个跨站关键结论至少有两个独立来源。遗漏一个附件会增加推理难度，但不会永久切断主线。

### 2.4 难度分层

主线证明“实验存在、证据可信、死人开关可启动”。隐藏线复核四处时间或权限矛盾，证明林知秋提前进入过系统，并改变最终选择。

## 3. 总体结构

第一章由三个独立发布的妙搭 HTML 应用构成：

| 应用 | 伪装身份 | 核心职责 |
|---|---|---|
| A | 林知秋的个人博客“看见缝隙的人” | 故事入口、病例调查、照片与草稿、最终选择 |
| B | 回声科技企业官网 | 公司公开叙事、历史快照、员工与删除记录 |
| C | 废弃档案镜像 `legacy.echo-mirror` | 内部目录、证词包、音频取证、哈希校验 |

跨站主循环：

1. A 提供公司名、日期、地点和案件编号。
2. B 提供陈砚明员工号、删除批次和残缺档案路径。
3. C 提供证词、上传日志、文件哈希和死人开关令牌。
4. 玩家回到 A 的隐藏控制页作最终选择。

不同妙搭应用之间不依赖共享 `localStorage`。跨站进度通过玩家已经掌握的案件号、员工号、路径和证据结论传递。

## 4. 调查阶段

### 4.1 阶段一：她留下了路线

预计 15–20 分钟。

玩家比较林知秋已发布的报道、自动保存草稿和编辑修订记录，恢复公开版本中被删除的第八段。

玩家应得出的结论：

- 林知秋在失踪前有意识地拆分调查材料。
- 钟楼街 29 号与 2019 年 3 月 15 日是她刻意留下的调查入口。
- 案件编号为 `ZL-0315`。

### 4.2 阶段二：病例不是随机的

预计 20 分钟。

玩家结合采访时间表、四张照片、图片元数据与城市停电公告，判断哪栋建筑与病例窗口吻合。

玩家应得出的结论：

- 病例发生时间并非随机。
- 照片中的安全出口灯只能来自具备备用供电的钟楼街 29 号旧实验楼。
- 照片反光中的标识将调查指向 Echo Technologies。

### 4.3 阶段三：公司在说谎

预计 25–30 分钟。

玩家比较回声科技 2019、2020 与当前三个网站快照，观察团队页、产品参数和新闻稿如何被修改，再分析资源请求日志。

玩家应得出的结论：

- 陈砚明的姓名、实验项目和异议声明在同一天被批量删除。
- 公司注销后，相关实验仍在继续。
- 陈砚明员工号为 `CYM-071`，删除批次为 `DEL-1109`。
- 残缺档案路径可重建为 `/legacy/CYM-071/DEL-1109/testimony.pkg`。

### 4.4 阶段四：启动死人开关

预计 20 分钟。

玩家取得损坏的证词包，在网页取证工具中修复文件头、分离左右声道，并核对上传日志与 SHA-256 摘要。

玩家应得出的结论：

- 陈砚明的证词经过剪辑，但核心内容可由日志和哈希交叉证明。
- 另一声道包含林知秋在失踪前录制的测试内容。
- 死人开关并非只有“立即公开”一种合理用法。

## 5. 页面设计

### 5.1 应用 A：个人博客

建议页面：

- `index.html`：延迟发送的私信。
- `blog.html`：博客首页及文章归档。
- `report.html`：最后一篇公开报道。
- `revision.html`：文章修订历史对比器。
- `attachments.html`：采访时间表、照片包与草稿下载。
- `photo-lab.html`：站内图片亮度、裁剪与元数据查看工具。
- `case-notebook.html`：统一案件笔记、三枚备忘和跨站提示入口。
- `dead-switch.html`：最终证据状态和结局选择。

应用 A 的主线产出：

- 钟楼街 29 号。
- 日期 `2019-03-15`。
- 案件号 `ZL-0315`。
- 回声科技名称与视觉标识。

### 5.2 应用 B：企业官网

建议页面：

- `index.html`：现行企业官网。
- `products.html`：公开产品和技术参数。
- `team.html`：当前团队资料。
- `archive.html`：三个年份的网站快照查看器。
- `diff.html`：页面版本差异视图。
- `directory.html`：历史员工目录。
- `request-log.html`：资源请求和删除日志筛选器。

应用 B 的主线产出：

- 陈砚明员工号 `CYM-071`。
- 删除批次 `DEL-1109`。
- 档案目录组成规则。
- 实验窗口仍在注销后持续的证据。

### 5.3 应用 C：档案镜像

建议页面：

- `index.html`：只读镜像入口。
- `tree.html`：残缺目录树。
- `package.html`：证词包下载与损坏提示。
- `forensics.html`：文件头修复、左右声道分离和波形检查。
- `integrity.html`：文件摘要与上传日志校验。
- `switch-console.html`：生成返回应用 A 的启动令牌。

应用 C 的主线产出：

- 可验证的陈砚明证词。
- 林知秋测试录音。
- 文件上传时间线与完整性结论。
- 死人开关启动令牌。

## 6. 核心谜题规格

### 6.1 P1：被删除的第八段

材料：

- 公开报道。
- 自动保存草稿。
- 编辑修订记录。

操作：

- 使用逐句差异视图恢复被删除内容。
- 判断删除是意外、审查还是林知秋主动布置。

正确结论：

林知秋主动将地点、日期和案件号从公开报道中拆出，留给收到死人开关的人。

### 6.2 P2：不可能的拍摄地点

材料：

- 四张候选照片。
- 采访时间表。
- 停电公告。
- 图片 EXIF 或等价元数据。

操作：

- 调亮暗部观察安全出口灯与反光标识。
- 比较拍摄时间和停电范围。
- 排除不具备备用供电的候选建筑。

正确结论：

照片拍摄于钟楼街 29 号旧实验楼，且林知秋亲自进入过该建筑。

### 6.3 P3：从官网消失的人

材料：

- 三个年份的官网快照。
- 团队页、产品页和新闻稿。

操作：

- 使用年份滑杆或差异模式对比页面。
- 记录同一天消失的人名、项目和声明。

正确结论：

陈砚明并非普通离职，相关信息在 `DEL-1109` 删除批次中被系统清理。

### 6.4 P4：404 日志里的档案

材料：

- 资源请求日志。
- 员工号。
- 删除批次。
- 残缺目录树。

操作：

- 按员工号与删除批次筛选。
- 根据请求先后顺序重建目录。

正确结论：

目标档案路径是 `/legacy/CYM-071/DEL-1109/testimony.pkg`。

此路径由行为日志推出，不通过查看源码猜测文件名。

### 6.5 P5：两个人说出的同一句话

材料：

- 损坏证词包。
- 双声道音频。
- 上传日志。
- 文件摘要。

操作：

- 在站内工具中识别并修复错误文件头。
- 分别试听左右声道。
- 对照关键秒点、上传时间和摘要记录。

正确结论：

陈砚明证词的核心内容可信，但文件曾被剪辑；林知秋在另一声道提前测试了死人开关。

## 7. 隐藏调查线

隐藏线由四枚“矛盾证据”构成：

1. 草稿文件的创建时间晚于文章表面发布时间。
2. 林知秋的相机在她声称未进入旧楼的时间拍摄过照片。
3. 她在陈砚明资料公开前就掌握了其内部员工号。
4. 死人开关在她失踪前被人工测试过一次。

单枚矛盾证据不阻断主线。集齐四枚后，玩家得到不同版本的林知秋录音，并解锁真结局。

每枚矛盾证据对应一个短证据片段。应用 B、C 不尝试读取应用 A 的状态，而是把证据片段明确交给玩家。玩家在应用 A 的案件笔记中提交四个片段，应用 A 才记录隐藏线完成状态。

隐藏线最终结论：

林知秋并非单纯被动失踪。她预料到系统会拦截公开证据，主动把死人开关设置成诱饵，并留下继续追踪资金流的路线。

## 8. 结局

### 8.1 结局 A：公开

玩家公开证据。页面先显示发布成功，随后出现大量互相矛盾的辟谣材料，暗示对方已准备好利用信息污染消解真相。

### 8.2 结局 B：暂缓

玩家保存证据但不立即发布。系统生成离线证据包，程野随后联系玩家，第二章由“继续调查”自然开启。

### 8.3 真结局 C：继续路线

仅在四枚矛盾证据齐全时出现。玩家识破死人开关的表层用途，使用林知秋留下的追踪令牌前往锦城。

第二章入口必须由玩家的结局选择触发，而不是常驻的续集链接。

## 9. 提示系统

玩家开局拥有三枚“林知秋备忘”。

三枚备忘统一保存在应用 A 的 `case-notebook.html`，避免三个来源各自发放提示。应用 B、C 的提示入口会携带当前谜题上下文返回应用 A；应用 A 扣除一枚备忘后展示对应桥接线索，并提供返回原页面的链接。

提示层级：

1. 叙事提示：角色文案提醒应比较或复核什么。
2. 方法提示：页面停留约 8 分钟后，可显示调查方向。
3. 操作提示：玩家主动展开后，提供具体工具操作，但不直接给结论。
4. 桥接兜底：约 15 分钟仍未推进时，可消耗一枚备忘补齐跨站桥接线索。

限制：

- 备忘不能替玩家完成核心证据判断。
- 隐藏线只提示未复核的材料类别，不提供异常的直接答案。
- 使用提示不阻止通关，但结尾可显示不同的调查评价。

## 10. 状态与数据流

每个应用只保存自身状态：

- 已阅读页面。
- 已完成工具步骤。
- 当前提示层级。
- 失败次数。
- 本站发现的隐藏证据。

状态保存在本应用来源下的浏览器存储中。跨应用不自动同步状态。

应用 A 是唯一的全局案件笔记：

- 保存三枚备忘的剩余数量。
- 接收玩家手动提交的四个隐藏证据片段。
- 接收应用 C 生成的死人开关启动令牌。
- 根据已提交材料决定最终可见的结局选项。

应用 B、C 通过普通链接的查询参数向应用 A 传递“当前需要哪类提示”等非敏感上下文。关键证据仍由玩家阅读、记录和提交，查询参数本身不代表谜题已完成。

跨站凭据包括：

- 案件号。
- 日期与地点。
- 员工号。
- 删除批次。
- 档案路径。
- 启动令牌。

站点在接受凭据时进行宽容标准化，但不会在输入框旁直接暴露格式答案。

## 11. 错误处理与兼容

### 11.1 文件处理失败

- 无法读取图片元数据时，站内取证工具显示等价的元数据导出。
- 浏览器不支持 Web Audio 时，提供波形图、分轨文字稿与可下载音频。
- 哈希计算失败时，允许玩家比较预生成摘要，但明确标记为兼容模式。

### 11.2 移动端

- 所有叙事内容和证据摘要可读。
- 复杂文件操作标记为“建议使用电脑调查”。
- 手机端提供降低沉浸感的兼容取证页，但不作为主要验收路径。

### 11.3 直接跳页

纯静态应用无法真正防止查看源码或直接访问 URL。设计不依赖安全性假象：

- 关键页面需要玩家掌握证据才能理解和完成。
- 答案校验使用浏览器端摘要或结构化证据组合，降低明文答案暴露。
- 不引入后端，除非未来明确要求跨设备同步、行为分析或真正访问控制。

## 12. 技术实现边界

技术栈：

- 原生 HTML、CSS、JavaScript。
- Web Audio API。
- File API。
- Web Crypto API 的 SHA-256 摘要。
- 妙搭 HTML 应用发布。

静态版可靠支持：

- 三个独立公开站点。
- 下载和上传调查文件。
- 图片与音频取证工具。
- 浏览器端文件摘要校验。
- 单站点本地进度和提示状态。

静态版不承诺：

- 跨设备同步。
- 不同妙搭应用自动共享进度。
- 真正防止源码查看或跳关。
- 管理员实时观察单个玩家。

## 13. 发布配置

跨站 URL 不直接散落在页面代码中。三个应用使用统一发布配置，例如：

```js
window.ARG_CONFIG = {
  blogUrl: "https://example.invalid/blog",
  corporateUrl: "https://example.invalid/echo",
  archiveUrl: "https://example.invalid/archive",
  chapter2Url: "https://example.invalid/chapter2"
};
```

发布顺序：

1. 创建并发布应用 B。
2. 创建并发布应用 C。
3. 将 B、C 正式 URL 写入应用 A 的发布配置。
4. 发布应用 A。
5. 将三个应用设置为互联网公开且免登录。
6. 从应用 A 入口完成全链路回归测试。

发布阶段需要用户完成一次：

```bash
lark-cli auth login --domain apps
```

本地设计和开发阶段不需要妙搭权限。

## 14. 测试

### 14.1 纸面测试

邀请 5 名未参与设计的人，只阅读材料和谜题规则，验证每个核心结论是否存在唯一合理解释。

### 14.2 可用性测试

邀请 8–12 名目标玩家，记录：

- 每个阶段耗时。
- 首次提出正确假设的时间。
- 提示使用次数。
- 错误假设及来源。
- 主线是否完成。
- 隐藏证据发现数量。
- 最终结局选择。

### 14.3 调整阈值

- 主线零人工提示通关率低于 70%：增加证据冗余或改进方法提示。
- 主线中位时长短于 65 分钟：提高信息组合深度，不增加机械步骤。
- 主线中位时长超过 100 分钟：减少材料噪声或缩短操作流程。
- 任一节点 P90 卡关超过 15 分钟：增加第二来源或桥接兜底。
- 真结局发现率低于 20%：增强隐藏线的存在感。
- 真结局发现率高于 40%：降低异常证据的显眼程度。

## 15. 验收标准

第一章重构完成需同时满足：

- 三个妙搭应用可以独立访问并正确跨站跳转。
- 玩家不查看答案文档即可完成主线。
- 五个核心谜题均要求提交证据或选择结论，而不是只输入字符串。
- 每个跨站关键结论至少有两个来源。
- 四枚隐藏证据均可独立发现且不会阻断主线。
- 三种结局有不同因果和内容。
- 第二章入口由结局触发。
- Chrome、Edge、Safari 桌面版完成全链路测试。
- 移动端可阅读全部剧情，并能识别何处建议切换电脑。
- 发布包不包含剧透文档、测试答案、开发配置或凭据文件。
