# 《寂静计划》ARG 页面设计系统 v1

## 1. 目标

为第一章现有 21 个页面建立统一、可执行的页面设计规范，解决页面紧凑、留白不足、同类页面结构漂移和移动端操作区域拥挤的问题。

本次改造只调整展示层：

- 不改变谜题答案、校验逻辑、剧情文本含义和结局条件。
- 不改变页面 URL、跨站路径、下载资源和 `localStorage` 数据结构。
- 不把三个站点改成同一种视觉风格。
- 不引入 CSS 框架、组件框架或构建依赖。

验收目标：

- 现有 21 个页面全部归入明确的主模板。
- 相同类型页面使用一致的容器、标题区、区块节奏和操作区。
- 桌面与移动端均不因紧凑布局压缩正文、按钮、表格或状态反馈。
- 博客、企业站和档案镜像仍能被玩家识别为三个不同的网站。

## 2. 已确认方向

### 2.1 骨架统一，皮肤独立

共享层统一：

- 页面容器和宽度。
- 纵向间距和网格。
- 标题层级。
- 面板、卡片、表格、表单、按钮和状态反馈。
- 五种语义页面模板。
- 响应式行为与可访问性状态。

站点皮肤独立：

- 博客保留纸张、衬线字体和编辑痕迹。
- 企业站保留冷蓝科技公司视觉。
- 档案镜像保留低照度终端视觉。

### 2.2 平衡留白

采用 8px 基础间距尺度，但允许 `12px` 等半阶值用于组件内部。设计 token 区分组件内部间距与页面布局间距，避免所有内容只依赖统一的 `margin-top`。

基础间距 token：

| Token | 值 | 用途 |
| --- | ---: | --- |
| `--space-1` | 4px | 图标、微型标签内部 |
| `--space-2` | 8px | 紧密关联元素 |
| `--space-3` | 12px | 标签与输入框、行内操作 |
| `--space-4` | 16px | 组件内部标准间距 |
| `--space-5` | 24px | 内容组、卡片内部 |
| `--space-6` | 32px | 主区块之间 |
| `--space-7` | 40px | 页面标题与首个主体区块 |
| `--space-8` | 48px | 大型叙事分段 |
| `--space-9` | 64px | 页面章节或营销区块 |

页面密度规则：

- 桌面页面左右安全边距为 `32–40px`。
- 移动端页面左右安全边距为 `16–20px`。
- 主区块间距为 `24–32px`。
- 组件内部标准间距为 `16–24px`。
- 页面底部保留至少 `64px`，避免最后一个操作贴近视口底边。

该尺度与 USWDS、Carbon Design System 的 token 化间距思路一致：使用离散尺度区分组件内部关系和页面布局关系，而不是为每个页面声明任意像素值。

## 3. CSS 架构

### 3.1 共享层

`src/shared/base.css` 负责：

- 原始视觉 token：间距、宽度、圆角、边框、阴影和控件高度。
- 语义颜色接口：页面背景、面板、正文、次要文本、主操作、警告、危险和成功。
- 共享布局：页面容器、阅读容器、数据容器、区块堆叠、双栏工作台。
- 共享组件：页面头部、面板、卡片、操作组、表单组、表格容器、状态条和证据块。
- 五种模板的结构规则。
- 通用响应式和键盘焦点规则。

共享层不直接规定博客纸张色、企业蓝或终端绿，只定义语义变量。

### 3.2 皮肤层

站点 CSS 文件只负责主题覆盖和站点专属组件：

- `src/blog/blog.css`
  - 纸张色、正文色、衬线阅读字体。
  - 聊天气泡、修订增删标记、照片取证图像和案件笔记。
- `src/corporate/corporate.css`
  - 企业蓝、导航、营销 Hero、网页快照和请求终端。
- `src/archive/archive.css`
  - 终端绿、目录树、十六进制、波形、哈希和日志动画。

皮肤文件不得重新定义页面最大宽度、通用面板间距、表单垂直节奏或按钮最小高度。需要差异时，通过共享层公开的语义变量覆盖。

### 3.3 HTML 使用约束

每个页面必须：

1. 选择一个主模板类。
2. 使用标准页面头部。
3. 把内容拆成有语义的主区块。
4. 使用标准操作组和状态反馈区域。
5. 仅在确有叙事意义时添加站点专属组件。

禁止通过连续 `<br>`、空段落或任意页面级 `margin` 制造布局。

## 4. 页面宽度

| 容器 | 最大宽度 | 用途 |
| --- | ---: | --- |
| 阅读容器 | 720px | 长文章、消息、结局文本 |
| 标准容器 | 1040px | 表单、卡片、普通调查页 |
| 数据容器 | 1120px | 表格、日志、双栏工作台 |
| 窄表单容器 | 640px | 单一输入或核验任务 |

正文行宽以约 45–75 个中文字符为目标。长文章不能因为标准页面宽度而铺满 1040px。

## 5. 五种语义模板

### 5.1 叙事阅读 `page--reading`

结构：

1. 可选的返回导航。
2. 眉题或时间信息。
3. 页面标题与导语。
4. 阅读正文。
5. 可选的下一步证据块或操作区。

规则：

- 使用阅读容器。
- 正文段落间距为 `1.1–1.3em`。
- 标题与首段之间至少 `24px`。
- 行高由皮肤决定，但不得低于 `1.65`。

### 5.2 调查工作台 `page--workspace`

结构：

1. 标准页面头部。
2. 调查目标和简短说明。
3. 材料区与分析/操作区。
4. 稳定的状态反馈。
5. 结论或后续证据区。

规则：

- 使用数据容器。
- 桌面端允许两栏，列间距为 `24px`。
- 主材料列不得小于总宽度的 55%。
- `760px` 以下变为单列，材料在前、操作在后。
- 结论区与工具区保持至少 `32px` 间距。

### 5.3 数据档案 `page--records`

结构：

1. 标准页面头部。
2. 标题、说明和可选筛选器。
3. 表格、日志、目录或文件元数据。
4. 可选的核验区或下一步操作。

规则：

- 使用数据容器。
- 表格放入标准滚动容器，不压缩关键字段。
- 表头、数据行和高亮行拥有统一高度。
- 筛选器与数据区之间保持 `16–24px`。
- 长路径、摘要和文件名允许换行，但保留可复制性。

### 5.4 核验表单 `page--verify`

结构：

1. 标准页面头部。
2. 任务说明。
3. 单一核心表单或核验动作。
4. 预留高度的状态反馈。
5. 成功后的下一步入口。

规则：

- 默认使用窄表单容器；与大型材料并列时可嵌入工作台模板。
- 每个表单字段使用标准字段组，标签、控件和说明不得挤在同一行。
- 字段组之间为 `20–24px`。
- 主操作与最后字段之间至少 `24px`。
- 成功、失败和处理中状态不得导致页面大幅跳动。

### 5.5 决策结果 `page--decision`

结构：

1. 状态或证据眉题。
2. 明确的结果标题。
3. 证据摘要或选择影响。
4. 一个主操作和可选的返回操作。

规则：

- 使用阅读容器或标准容器。
- 选择卡片按纵向堆叠，卡片之间为 `16px`。
- 重要结果与普通说明在色彩、边框和留白上有明确层级。
- 不在同一视觉层级放置多个主按钮。

## 7. 共享组件规范

### 7.1 页面头部

- 由站点标识、页面上下文和返回操作组成。
- 桌面端同一行，移动端允许换行。
- 头部下方与页面标题之间至少 `32px`。
- 返回操作不得与页面主操作使用相同视觉权重。

### 7.2 标题区

- 每页仅一个 `h1`。
- 标题区顺序为眉题、`h1`、导语。
- `h1` 使用流式字号，普通页面约 `36–56px`，阅读文章可由皮肤调整。
- 导语最大宽度为 `65ch`。

### 7.3 面板与卡片

- 面板用于完整任务区块，内部间距 `24px`。
- 卡片用于同级可比较项目，内部间距 `16–20px`。
- 同一页面不得同时出现多个无语义差异的圆角与边框规格。
- 面板不再依赖全局 `margin-top`；由父级区块堆叠控制间距。

### 7.4 表单

- 标签显示在控件上方。
- 输入框和选择框最小高度 `44px`。
- 按钮最小高度 `44px`。
- 主操作使用实心强调色，次操作使用描边或文本样式。
- 状态反馈区域最小高度约为两行文本，避免提交后布局跳动。
- 错误文本必须说明哪类证据不成立，不能只依赖颜色。

### 7.5 操作组

- 同组操作间距为 `8–12px`。
- 桌面端可横排，移动端默认允许纵向铺满。
- 危险操作和下一步操作不得并排使用同一视觉权重。

### 7.6 表格与日志

- 外层必须提供水平滚动。
- 单元格标准垂直内边距为 `12–14px`。
- 表头必须与数据区形成颜色或字重区别。
- 关键路径列可设最小宽度，避免被压缩成逐字换行。
- 高亮记录同时使用边框、背景或标签，不只依赖文字颜色。

### 7.7 证据与状态

统一状态类别：

- `info`：调查说明。
- `pending`：等待输入或计算。
- `success`：证据成立。
- `warning`：材料不完整或兼容模式。
- `danger`：证据冲突或无效。

证据片段使用站点皮肤强调色，但尺寸、内边距和字距由共享层控制。

## 8. 站点皮肤

### 8.1 博客皮肤

- 背景保持暖色纸张。
- 长文使用衬线字体，工具和表单使用系统无衬线字体。
- 修订删除为暖红，新增为低饱和绿色。
- 纸张页面的边框和次要文字必须满足可读性，不能用过浅米色。

### 8.2 企业皮肤

- 使用深蓝背景和冷蓝强调色。
- 导航与数据页面使用无衬线字体。
- Hero 可以突破标准容器，但后续内容必须回到统一容器。
- 终端日志是企业站专属组件，不改变共享表格与操作规范。

### 8.3 档案皮肤

- 使用近黑背景、浅绿色正文和更亮的状态强调。
- 等宽字体用于路径、哈希、日志和文件头；说明文字可以使用系统字体以提高中文可读性。
- 动画只用于日志揭示，不承担唯一的信息传递功能。
- 终端氛围不得通过压缩字号和行距实现。

## 9. 响应式规则

断点：

- `760px`：双栏工作台转单列，导航允许换行。
- `560px`：操作组默认纵向，面板内边距降至 `16–20px`。

移动端规则：

- 页面标题不小于 `30px`。
- 正文不小于 `16px`。
- 输入、选择和按钮保持至少 `44px` 高。
- 表格横向滚动，页面本身不出现横向溢出。
- 双栏顺序必须保持“材料在前，操作在后”。
- 不能通过缩小控件或字号来强行维持桌面布局。

## 10. 可访问性

- 所有交互控件保留明显的键盘焦点，焦点轮廓目标为至少 `2px`。
- 指针目标至少满足 WCAG 2.2 的 `24×24px` 最低要求；本项目主要按钮和表单控件采用 `44px` 高度。
- 颜色不是成功、失败、删除和新增状态的唯一表达方式。
- `prefers-reduced-motion: reduce` 下关闭非必要过渡与日志动画。
- 页面缩放至 200% 时，核心内容和操作仍可访问。
- 标题层级、表单标签、状态区域和表格语义保持正确。

## 11. 实施边界

实施允许：

- 重构 `src/shared/base.css`。
- 调整三个站点 CSS 中的主题变量和专属组件。
- 为 21 个 HTML 页面增加模板类、容器类和语义区块。
- 为表格补滚动容器，为表单补标准字段组。
- 修复由现有紧凑布局造成的响应式展示问题。

实施不允许：

- 改写谜题内容或答案。
- 改变 JavaScript 中的校验条件。
- 改变资源文件、哈希、音频或下载路径。
- 改变 URL 和跨页面导航。
- 引入新的生产依赖。
- 将全部页面做成同一种配色或字体。

## 12. 测试与验收

### 12.1 自动测试

新增或扩展测试以验证：

- 21 个页面均声明一个有效主模板。
- 页面只有一个 `h1`，并保留语言、标题和 viewport。
- 所有表格位于可滚动数据容器。
- 所有表单拥有标准字段组、操作组和状态区域。
- 构建产物链接继续有效。
- 原有谜题、资源完整性和结局测试继续通过。

### 12.2 浏览器验收

代表页面：

- 叙事阅读：`blog/report.html`。
- 调查工作台：`blog/photo-lab.html`。
- 数据档案：`corporate/request-log.html`。
- 核验表单：`archive/integrity.html`。
- 决策结果：`blog/case-notebook.html`。
- 特殊营销变体：`corporate/index.html`。

每个代表页面在以下视口检查：

- 桌面：`1280×720`。
- 平板：`768×1024`。
- 手机：`390×844`。

验收项：

- 页面不再呈现连续面板贴合或标题紧贴内容。
- 主操作位置明确。
- 状态反馈不会造成明显布局跳动。
- 表格和长路径不破坏页面宽度。
- 三个站点视觉身份仍然明显不同。
- 浏览器控制台无新增错误或警告。
